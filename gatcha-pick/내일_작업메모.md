# Gatcha-Pick 작업 메모 — 2026-11-11

내일 이어서 하기 전 이 문서를 먼저 읽는다. 사용자가 준 레이아웃 이미지와 원본 에셋이 기준이다. 임의로 새 디자인을 만들거나 이미지 구도·위치를 바꾸지 않는다.

## 현재 파일과 작업 상태

- 시작 화면: `index.html`, `startPage.css`, `startPage.js`
- 다음 메인 화면: `mainPage.html`, `mainPage.css`, `mainPage.js`
- 공통 커서: `cursor.js`
- 첫 화면 원본: `1st_img/`
- 둘째 화면 원본: `2st_img/`
- 디자인 기준 이미지: `img/메인참고.png`; 분위기 참고는 `img/가챠픽 무드보드.png`
- 이 폴더의 화면 코드는 로컬 프로젝트다. 오늘의 공개 배포는 별도 포트폴리오(`portfolio/aboutMe.html`, Sites v8)만 대상으로 했다. Gatcha-Pick을 배포했다고 말하지 않는다.
- 오늘 이 폴더에 추가한 것은 이 메모뿐이다. 다음 작업 전 현재 HTML/CSS/JS와 에셋을 확인하고, 요청된 변경 외에는 수정하지 않는다.

## 절대 지킬 디자인 지시

- `1st_img/메인_시작.png`는 참고용 무드가 아니라 그대로 재현해야 하는 디자인 원본이다. 이 이미지를 바탕으로 요소를 배치한다. 새 레이아웃이나 새 그림으로 대체하지 않는다.
- 2페이지의 기본 구성과 비율은 `2st_img/메인참고.png` 그대로 따른다. 스크롤 없이 한 캔버스 안에서 모든 요소를 보여준다.
- 바깥 문서 배경은 흰색이고 회색은 참고 이미지 비율의 중앙 캔버스 안에만 둔다. 두 페이지 모두 중앙 정렬이다.
- 두 페이지 캔버스 테두리는 `2px solid #000`이 맞다. 현재 두 CSS 파일의 설정을 유지한다.
- 레트로 픽셀아트와 Windows XP 느낌을 유지한다. 무드보드는 분위기 참고이고 원본 레이아웃을 바꾸는 근거가 아니다.
- 모든 요소를 중앙 정렬하라는 지시는 캔버스/전체 화면 배치에 적용한다. “텍스트 좌측 정렬” 지시는 로딩 문구 내부 정렬에 적용한다.

## 시작 화면 — `index.html`

### 재생 순서와 원본 에셋

1. `메인_1.png` + `초록공선.png` + `roading.`
2. `메인_2.png` + `초록공 깐.png` + `다접은 종이.png` + `roading..`
3. `메인_3.png` + `초록공 깐.png` + `카와 편종이.png` + `roading...`
4. 위 1→2→3을 한 번 더 반복한다.
5. 그 뒤 `메인_시작.png`를 표시하고 시작 버튼을 노출한다.

- 프레임 간격은 현재 `frameDurationMs = 600`이다. 사용자는 초기 1~3 진행을 0.2초 빠르게 해달라고 요청했다. 현재 코드에 반영된 값이 600ms다. 별도 요청 없이 속도를 다시 바꾸지 않는다.
- 공과 종이가 변할 때 crossfade나 transition을 넣지 않는다. 다음 원본 상태로 바로 교체한다.
- 로딩 문자열은 정확히 `roading.` / `roading..` / `roading...` 순서다. 글자 덩어리는 고정하고 점만 오른쪽에 하나씩 추가되는 것처럼 왼쪽 정렬한다. 점 아래 짧은 밑줄은 없다.
- 화면의 모든 요소를 기준 이미지에 맞춰 중앙 캔버스 안에 배치한다. 본문을 비워 둔 영역을 활용해 공/버튼을 배치해 첫 세 프레임과 시작 화면에서 위치가 어긋나지 않게 한다. 시작 화면에서는 버튼 위 공을 제거한다.
- 기존 공·종이 PNG가 브라우저에서 과하게 깨져 보이지 않도록 원본 크기와 렌더링을 확인한다. 사용자가 새로 넣은 이미지를 중복 표시하거나 같은 위치에 겹쳐 공 두 개처럼 보이게 하지 않는다.

### 시작 버튼, 커서, 헤더

- 기본/호버/클릭 에셋은 각각 `1st_img/시작버튼.svg`, `시작호버.svg`, `시작클릭.svg`를 사용한다. `메인_시작.png`를 호버하면 시작 호버, 클릭하면 클릭 상태를 표시하고 `mainPage.html`로 간다.
- 문서 전체 사용자 정의 커서는 `1st_img/커서.svg`다. 사용자가 SVG라고 명시한 파일명이 실제로 `.svg`인지 확인하고, 오타를 새로 만들지 않는다. 현재 `cursor.js`는 마우스 이동 때 커서를 따라가게 한다. CSS 표시 크기는 45px이다.
- 우측 상단 장식은 기존 회색 네모를 가리는 `헤더 분홍 공.svg` 하나만 기존 분홍 공 위치에 표시한다. 중복된 핑크 공을 겹쳐 보이게 하지 않는다. 위치는 기존 좌표에 맞춘다.
- 시작 화면 기본 폰트는 `../Font/GalmuriMono11.ttf`이며 현재 CSS의 `@font-face` 이름은 `GalmuriMono11Local`이다.

## 다음 메인 화면 — `mainPage.html`

- 전체 구성 원본은 `2st_img/메인참고.png`다. 참고만 하고 새로 디자인하지 않는다. 상단 파란 영역도 시작 화면과 동일한 스타일/위치 기준을 유지한다.
- 하단 반복 머신은 `2st_img/머신.svg`를 사용한다. 왼쪽으로 천천히 무한 이동한다. 기준 속도는 `test_LEEKIJOO.html`의 자동 무한 머신보다 아주 조금 느리게 한다. 현재 `mainPage.js`는 기준 속도의 95%로 duration을 계산한다.
- 각 머신 흰 창마다 공 4개가 자동으로 계속 굴러간다. 현재 색은 파랑·보라·민트·빨강(`2st_img/공/`)이다. 모든 머신은 같은 색 배열과 같은 굴러가는 모션을 사용한다.
- 버튼은 `어디갈까 버튼.svg`, `뭐먹을까 버튼.svg`의 기본 이미지와 각각의 호버/클릭 이미지를 그대로 쓴다. 버튼 클릭 후 선택 상태는 유지한다.
- 현재 `mainPage.html`은 하나의 중앙 캔버스이며 `overflow:hidden`으로 페이지 스크롤을 막는다.

## 내일의 확인 순서

1. 이 메모와 `index.html`, `startPage.css`, `startPage.js`, `mainPage.html`, `mainPage.css`, `mainPage.js`를 먼저 읽는다.
2. 두 `.design-canvas`의 테두리는 `2px solid #000`을 유지한다.
3. 브라우저에서 원본 `메인_시작.png`와 실제 시작 화면을 나란히 비교해 버튼/공 위치와 핑크 공 중복 여부를 본다.
4. 로딩 순서, 점 추가 방향, 1~3 반복 횟수, 프레임 간 전환에 페이드가 없는지 확인한다.
5. 시작 버튼 세 상태와 `mainPage.html` 이동을 확인한다.
6. 메인 캔버스가 중앙에 있고 바깥은 흰색인지, 스크롤이 없는지, 머신이 끊김 없이 왼쪽으로 반복되는지, 공 4개/버튼 상태가 작동하는지 확인한다.
7. 배포는 별도 요청이 있거나 기존 작업 흐름에서 명시적으로 진행할 때만 다룬다. 포트폴리오 Sites 주소와 Gatcha-Pick 로컬 파일을 혼동하지 않는다.

## 변경할 때 금지할 것

- 사용자가 올린 기준 이미지를 “참고”로만 취급하고 재해석해 레이아웃을 다시 그리는 것.
- 요청한 위치를 유지하라고 했는데 임의로 옮기거나, 공/종이/버튼을 중복 표시하는 것.
- 자산을 비슷한 새 이미지나 임의 SVG로 교체하는 것.
- 기존 1페이지 동작을 고칠 때 2페이지까지 같이 손대거나, 한 페이지만 고치고 두 페이지 공통 요구를 놓치는 것.
- 간단한 CSS 수정으로 해결할 수 있는 커서 크기를 이유로 사용자에게 다시 물어보는 것.
- 실제 브라우저에서 확인하지 않았는데 확인했다고 기록하는 것.
